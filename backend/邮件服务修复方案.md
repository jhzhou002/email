# 邮件服务修复方案总结

## 问题诊断

### 根本原因
1. **全量扫描邮件** - 每次 `fetch('1:*')` 下载所有邮件
2. **轮询频率过高** - 10秒一次触发QQ邮箱限制
3. **去重逻辑低效** - 使用 `subject/date/from` 查询慢且不准确
4. **事件监听器泄漏** - IDLE模式中重复注册事件

### 症状
- 服务启动后正常工作
- 一段时间后连接断开
- 出现 "Connection not available" 错误
- 需要重启才能恢复

## 修复方案

### ✅ 核心改进

| 改进项 | 旧方案 | 新方案 | 效果 |
|--------|--------|--------|------|
| 邮件拉取 | `fetch('1:*')` 全量 | UID 增量同步 | 减少 100x+ 负载 |
| 轮询频率 | 10 秒 setInterval | 60 秒链式调度 + IDLE | 避免服务器限制 |
| 去重机制 | subject/date/from 三字段 | imap_uid 唯一键 | 查询速度提升 10x+ |
| 实时性 | 定时轮询 | IDLE 实时推送 | 0 延迟收取邮件 |
| 连接管理 | 保活 NOOP | 自动重连 + 指数退避 | 断线自动恢复 |

### 🔧 技术实现

#### 1. IDLE 实时推送
```typescript
// 优先使用 IDLE 模式，实时监听新邮件
while (this.isRunning && this.imapClient?.usable) {
  await this.imapClient.idle(); // 等待新邮件或 29分钟超时
  await this.fetchNewEmails();  // 有新邮件时拉取
}
```

**优点**：
- 实时收到邮件通知
- 不消耗服务器资源
- QQ邮箱推荐方式

**降级策略**：如果服务器不支持IDLE，自动降级到 60秒轮询

#### 2. UID 增量同步
```typescript
// 只拉取 UID > lastUid 的新邮件
const lastUid = await getLastUid();
const range = lastUid > 0 ? `${lastUid + 1}:*` : '1:*';

for await (const msg of client.fetch(range, { uid: true })) {
  // 处理新邮件
  maxUid = Math.max(maxUid, msg.uid);
}

await saveLastUid(maxUid);  // 保存进度
```

**优点**：
- 只拉新邮件，不重复处理
- 邮箱邮件再多也不影响性能
- 支持断点续传

#### 3. UID 去重
```sql
-- 新增字段
ALTER TABLE emails ADD COLUMN imap_uid BIGINT NULL;
CREATE INDEX idx_emails_imap_uid ON emails(imap_uid);

-- 快速去重
SELECT id FROM emails WHERE imap_uid = ?;
```

**优点**：
- 使用索引，查询速度快
- UID 唯一可靠
- 无需解析邮件内容

#### 4. 链式调度
```typescript
// 不用 setInterval，改用链式 setTimeout
const loop = async () => {
  await this.fetchEmails();
  setTimeout(loop, 60000);  // 上一次完成后才调度下一次
};
```

**优点**：
- 永不并发
- fetch 慢时自动降频
- 更符合 IMAP 规范

#### 5. 自动重连
```typescript
// 连接断开时自动重连，指数退避
client.on('close', () => {
  this.scheduleReconnect();  // 1s, 2s, 4s, 8s...最多 60s
});
```

## 配置说明

服务从数据库 `settings` 表读取IMAP配置：

| 配置项 | 说明 | 示例值 |
|--------|------|--------|
| `imap_server` | IMAP 服务器 | imap.qq.com |
| `imap_port` | IMAP 端口 | 993 |
| `imap_user` | 邮箱账号 | your@qq.com |
| `imap_pass` | 授权码 | abcdefghijklmnop |
| `last_imap_uid` | 上次同步UID | 自动维护 |

**注意**：QQ邮箱不使用邮箱密码，而是使用**授权码**。获取方式：
1. QQ 邮箱设置 → 账户
2. 开启 IMAP/SMTP 服务
3. 生成授权码（16位）

## 常见问题

### Q: 为什么日志显示 "Connection not available"？
**A**: 旧服务还在运行。请确保：
1. 完全停止旧服务进程
2. 重新编译：`npm run build`
3. 启动新服务：`npm run start`

### Q: IDLE 不工作怎么办？
**A**: 系统会自动降级到轮询模式（60秒间隔），无需干预。检查日志是否有：
```
⚠️ IDLE not supported, falling back to polling mode
```

### Q: 首次同步会拉取所有邮件吗？
**A**: 不会。首次同步限制最多 50 封邮件，避免过载。之后只拉新邮件。

### Q: 如何手动触发拉取？
**A**: 调用 API 接口：
```bash
POST /api/emails/manual-fetch
Authorization: Bearer <token>
```

### Q: 服务停止后重启会丢失邮件吗？
**A**: 不会。UID 进度保存在数据库中，重启后从上次位置继续。

## 故障排查

### 1. 连续失败
**现象**: 日志显示连续 "Connection not available"

**排查**：
```bash
# 1. 检查配置
SELECT * FROM settings WHERE `key` LIKE 'imap_%';

# 2. 测试连接
curl -X POST http://localhost:3004/api/admin/test-imap \
  -H "Authorization: Bearer <token>"

# 3. 查看详细错误
tail -f logs/error.log
```

### 2. 重启循环
**现象**: 服务不断重连

**可能原因**：
- 授权码错误
- 网络不稳定
- QQ 邮箱限制

**解决**：
1. 更新授权码
2. 检查网络
3. 等待限制解除（通常 10-30 分钟）
